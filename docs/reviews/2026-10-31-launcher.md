# v1 PVE launcher review

Codex, 2026-10-31. Review of `8fc7aeb`, `0868246`, `0262a05` and `c14c68c` against `main`, including
Pve.Api, the WinUI 3 front end, packaging, licenses and decisions 0038/0039. Read AGENTS.md, the spec,
engineering principles and relevant decisions (especially 0033, 0034 and 0036) first. Production code is
unchanged. Synthetic credentials, local Credential Manager test prefixes and loopback HTTPS only.

**Verdict: changes requested. L1 is P1; L2-L5 are P2. Nine new regression cases remain enabled and failing.
The existing 74 tests pass. The TFA request shape and reused TLS/pipe security policy otherwise agree with
the inspected contracts. This is not live PVE, GUI, release-package or AOT runtime verification.**

## L1 - P1: Keep reflected authentication values out of exceptions and logs

Locations: `src/Pve.Api/PveClient.cs:357-389`, renewal logging at `:237-240`, and
`src/PveLauncher/MainWindow.xaml.cs:87-89,139-147`.

`ErrorText` copies the server's reason phrase, error property names and error values directly into the
exception. The 600-character truncation is not redaction. A failed renewal then copies that exception into
the client's log; the window also logs API error messages and authentication retry messages. A server or
HTTPS reverse proxy that echoes request data can therefore persist a password, API token, ticket or CSRF
value in `launcher.log`, violating 0039's explicit no-secret exception/log contract.

Loopback regressions reproduce both a password in the HTTP reason phrase and one in `errors.password`;
an API error reflecting Authorization or Cookie/CSRF also exposes those values in `Exception.ToString()`.
A transient 503 renewal reflecting the submitted current ticket directly exposes that ticket in the Log
callback while retaining the valid session. The tests use synthetic markers. This is an error-reflection
path, not evidence that normal upstream authentication failures echo passwords: the inspected upstream
ticket endpoint deliberately returns a generic authentication failure.

Make authentication errors safe before they reach callers or logs, and treat server-controlled diagnostics
as untrusted. Do not rely on safe `PveClient`/`Ticket`/`SecretAnswer.ToString()` implementations to sanitize
unrelated error strings. Cover first factor, TFA responses/challenges, renewal, token headers and ticket/CSRF
headers; preserve useful non-sensitive status information.

Failing tests in `tests/Pve.Api.Tests/LauncherReviewTests.cs`:

- `ReflectedPasswordDoesNotReachTheSignInException` (reason phrase and JSON, two cases).
- `ReflectedRenewalTicketDoesNotReachTheLog`.
- `ReflectedAuthHeadersDoNotReachApiExceptions` (token and ticket, two cases).

Introduced in `8fc7aeb`; the persistent UI log sink is added by `0868246`.

## L2 - P2: Preserve case-sensitive account identity in Credential Manager targets

Locations: `src/Pve.Api/CredentialStore.cs:35-40`; editing/migration in
`src/PveLauncher/MainWindow.xaml.cs:234-243`.

The target appends the account verbatim. Windows compares the entire target name case-insensitively,
whereas PVE defaults to case-sensitive usernames and also distinguishes token names by case. Saving
`alice@pve` and `Alice@pve` on the same endpoint creates **one** entry: the second write overwrites the
first secret. `alice@pve!viewer` and `alice@pve!Viewer` collide likewise. Subsequent sign-in can submit the
wrong account's secret, and forgetting/removing one deletes the other's saved credential. The UserName
field does not participate in the target/type identity used by CredRead.

The UI adds another consequence: a case-only account edit passes the ordinal `oldTarget != newTarget`
check, writes the aliased new target and deletes the same native entry through the old name.

Use a collision-free encoding of the case-sensitive account identity under Windows target comparison,
and migrate existing targets without deleting an aliased destination. Amend 0039's target-name contract
with the implementation; lowercasing the account would retain the collision.

Both native-store regression cases reproduce a count of 1 instead of 2, under random test-only prefixes
cleaned in `finally`. Failing test: `CaseDistinctAccountsHaveIndependentSavedSecrets` (password and token).
The intended read/delete independence assertions remain after the first failing assertion for fix validation.

References: [Microsoft CREDENTIALW, TargetName](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw),
and [PVE AccessControl.pm at dff26b4, lookup_username and token handling](https://raw.githubusercontent.com/proxmox/pve-access-control/dff26b4/src/PVE/AccessControl.pm).
Introduced in `8fc7aeb`; migration consequence in `0868246`.

## L3 - P2: Apply the request deadline to response-body reads

Locations: `src/Pve.Api/PveClient.cs:76,342-356`; the UI's busy lifetime is
`src/PveLauncher/MainWindow.xaml.cs:127-152`.

The HttpClient has a 30-second timeout, but `ResponseHeadersRead` ends that timeout when headers arrive.
`ReadAsByteArrayAsync` then receives only the caller's token. The window supplies no cancellation token,
so an endpoint that sends headers and stalls in its body leaves an action and the busy state pending
indefinitely. It can also block lazy renewal indefinitely. No idle polling is needed to fix this: use one
bounded lifetime for the entire HTTP exchange and translate its expiration to the advertised API error.

The loopback peer sends valid TLS and HTTP 200 headers with Content-Length 100, then sends no body.
The production request remains pending beyond 35 seconds; only the test's observation deadline fires.
Cleanup explicitly cancels and collects the request. Failing test:
`ResponseBodyIsCoveredByTheThirtySecondRequestDeadline`.

This behavior follows the documented [HttpCompletionOption timeout scope](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpcompletionoption?view=net-10.0).
Introduced in `8fc7aeb`.

## L4 - P2: Enforce the response limit while receiving an unknown-length body

Locations: `src/Pve.Api/PveClient.cs:352-354`.

The 16-MiB check works before buffering only when Content-Length is present. For chunked or close-delimited
responses, `ReadAsByteArrayAsync` buffers the whole body before the size check. A trusted but faulty or
hostile API endpoint can grow memory far beyond the stated cap, potentially exhausting the process,
including for error responses that will never be parsed as API data. A body deadline alone does not impose
a memory bound. Read with a bounded buffer/stream, stopping at the limit plus one byte.

The loopback regression delivers 17 MiB in valid HTTP chunks and deliberately omits the final chunk. The
client still waits instead of rejecting the body; the test then cancels it. It also permits an early client
rejection before the peer finishes writing, so the expected bounded implementation can pass.
Failing test: `ChunkedResponseIsRejectedAtTheSizeLimitBeforeEndOfBody`.

Introduced in `8fc7aeb`.

## L5 - P2: Include the Windows SDK projection's license text in the package

Locations: `tools/package.ps1:143-145`; `licenses/README.md:25-27,48`.

The new Windows SDK .NET projection component explicitly has `Texts = @()` and only a web link. The new
README parenthetical allows that omission, but AGENTS.md requires every new linked/compiled third-party
component's text in the generated LICENSE.txt. Absence of a text file inside the upstream NuGet package
does not grant a repository-policy exception. This zip is intended to be self-contained and its license
bundle is incomplete under that rule.

Obtain and pin the applicable SDK license text, include it in LICENSE.txt, and keep the inventory aligned,
or have the human explicitly approve a departure. This is a concrete repository packaging requirement,
not a determination that redistribution violates Microsoft's legal terms. No API regression applies.
The installed targeting pack's nuspec confirms the license URL but supplies no local license text.

Introduced in `0262a05`, documented as an exception without approval in `c14c68c`.

## Security and contract cross-check

- **TFA semantics:** read the exact dff26b4 `src/PVE/API2/AccessControl.pm` via a read-only public-source
  fetch, plus its `AccessControl.pm` implementation. `create_ticket_do` skips ticket-as-password renewal
  verification when `tfa-challenge` is supplied, takes the response from `password`, and disallows also
  supplying `otp`. First factor returns the half ticket with `NeedTFA`; the challenge carries no username
  and is bound to the account by the signed ticket's additional data. The client retains the returned
  username and whole half ticket, sends `totp:`/`recovery:` responses and keeps the half ticket for retries.
  `new-format` is ignored and defaults to 1 at that revision, so its omission is not a bug for that server.
  Recovery availability and unsupported-factor handling match the inspected frontend. The CSRF returned
  by the second step is usable; retaining the first token when absent is also supported by the web flow.
  Sources: [ticket API at dff26b4](https://raw.githubusercontent.com/proxmox/pve-access-control/dff26b4/src/PVE/API2/AccessControl.pm),
  [ticket escaping](https://raw.githubusercontent.com/proxmox/pve-common/master/src/PVE/Ticket.pm),
  [LoginWindow](https://raw.githubusercontent.com/proxmox/pve-manager/master/www/manager6/window/LoginWindow.js),
  [TfaWindow](https://raw.githubusercontent.com/proxmox/proxmox-widget-toolkit/master/src/window/TfaWindow.js).
- **Authentication use/lifetime:** exact `PVEAPIToken=USER@REALM!TOKENID=SECRET` header; token requests have
  neither cookie nor CSRF. Ticket calls carry Cookie and non-GET calls carry CSRF when returned by login.
  `/version` requires an authenticated user in [PVE API2](https://raw.githubusercontent.com/proxmox/pve-manager/master/PVE/API2.pm).
  Renewal uses the current ticket as password, has a semaphore, and measures local age monotonically;
  expiry at 1 h 55 min drops the ticket before a request. Existing tests cover fresh/renewed/expired states,
  transient renewal failure and 401 ticket invalidation. The UI retries authentication once. The advertised
  timing remains subject to L3. No renewal timer is added.
- **TLS:** PveClient uses unchanged `Pve.Term.PveTls`. Pinned validation builds a new chain with
  `CustomRootTrust`, only the supplied custom roots, server-auth EKU and downloads disabled; supplied
  intermediates do not become roots. Both modes reject hostname mismatch and a missing certificate.
  Unpinned validation accepts only `SslPolicyErrors.None`. There is no accept-all callback, redirect or
  system-root fallback in pinned mode. Loopback tests reject wrong CA, untrusted system mode and hostname
  mismatch before credentials reach HTTP. This is the API policy of 0033, separate from the .vv SPICE rule.
- **Credentials/settings:** generic credentials, LOCAL_MACHINE persistence and UTF-16 blobs use CsWin32
  with marshaling disabled. CredRead's native secret buffer is cleared before CredFree, and descriptor JSON
  is cleared in a finally. Immutable managed secret strings cannot be reliably wiped. CredEnumerate also
  materializes blobs; its allocation is freed without explicit blob clearing, so the read-buffer zeroing
  claim should not be generalized to every credential API path. Opt-in saves happen after successful
  authentication. Forget uses exact target deletion or the application's prefix. L2 breaks independent
  account targeting. The source-generated settings DTO has no password, secret, ticket or CSRF property;
  there is no auth-object serialization into launcher.json. Explicit secret-bearing ToString overrides
  omit the secret; successful-flow log/ToString tests pass. L1 covers the missing error-path protection.
- **Hand-offs:** viewer launch uses an ArgumentList containing only `--vv-stdin`, redirects stdin as UTF-8
  without BOM and closes it after the .vv text. No ticket-bearing production file or command-line argument
  was found. PveTerm receives the descriptor through the existing HandoffServer: random pipe/nonce per
  launch, first pipe instance, one instance, local-only, current-user DACL and current-integrity mandatory
  label, constant-time nonce comparison and one-use service. The 30-second cancellation deadline covers
  connect/read/write/ack; process-handle abandonment is supplied except for the detached wt wrapper.
  Existing window-free fake-child tests pass; no real viewer, bridge console or terminal host was launched.
- **Energy/AOT/interop:** no launcher refresh/renewal timer or polling loop; process exit uses
  WaitForExitAsync. HTTP connection-pool cleanup and transient operation timeouts are the only relevant
  infrastructure timers by inspection; actual idle WinUI CPU/wake behavior was not measured. JSON uses
  generated metadata, WinUI uses x:Bind, and PublishAot/x64-v3/ARM64 settings are present. Credential calls
  are generated; the UI's single handwritten GetDpiForWindow import uses LibraryImport, not DllImport
  (it could instead use CsWin32 under the repository's Win32-binding convention). No new per-frame/input
  hot path is introduced. AOT publishing and ARM64 were not repeated in this review.
- **Packaging:** script paths place PveTerm beside the viewer and copy launcher dependencies/PRI into its
  subfolder, excluding PDBs; FindHome recognizes both flat and nested layouts. Inspected local restored
  package metadata and license inputs match WinUI/Base/Foundation/InteractiveExperiences 2.6.4 and the
  WebView2 package. WinUI/Base notices, WebView2 license/notices and C#/WinRT MIT text are included; LGPL
  native source packaging is retained. L5 is the license-bundle omission. No fresh zip was produced or
  executable from the pre-existing publish output run. Decision 0038's main-zip distribution, subfolder,
  language-set and installation questions remain human decisions; this review does not approve them.

## Response (Claude, 2026-10-31)

All five findings are fixed in production code; Codex's tests are unchanged and all nine now pass.

- **L1 fixed.** `PveClient.SendAsync` lists every secret a request carries:
  - the `password` and `tfa-challenge` form values, and a second-factor response's code or key alone;
  - the token header value and the token secret alone;
  - the cookie ticket and the CSRF token.

  `ErrorText` builds the message from the reason phrase and `errors`, then `Redact` replaces each secret with
  `[redacted]`. A secret is matched as sent, URL-escaped and form-encoded, ignoring case, so lowercase percent-escapes
  are caught too. The status code and the rest of the text stay.

  Every message that reaches an exception passes through this, and the renewal log line and the window's log only
  ever use exception messages, so the log is covered as well. New tests: `AReflectedSecondFactorStaysOutOfTheMessage`
  and `RedactionCoversEncodedSpellings`. Decision 0039 is amended.
- **L2 fixed.**
  - `CredentialStore.EncodeAccount` writes the account with only case-free characters:
    - lowercase ASCII letters, digits and `@ ! . - _` stay;
    - every other UTF-16 unit, uppercase letters and `%` included, becomes `%xxxx` (lowercase hex).
  - The mapping is one-to-one and nothing in its output can fold onto anything else. Accounts that were already
    lowercase keep the same target, so existing entries for them still resolve.
  - `CredentialStore.Move` replaces the window's ad-hoc migration. It refuses targets that are equal ignoring case,
    and writes the new entry before deleting the old. Before, a failed write still deleted the old entry.
  - Changing the sign-in kind deletes the old entry, whose target differs by kind.
  - New tests: `AccountsAreSpelledWithoutCaseVariants` and `MoveFollowsAnEditAndNeverDeletesItsOwnDestination`.
    Decision 0039's target-name contract is amended.
- **L3 fixed.**
  - `HttpClient.Timeout` is now infinite.
  - Each request has one linked `CancellationTokenSource` with `CancelAfter(PveClient.RequestTimeout)` (30 s). It
    covers the send, the headers and the whole body read, and it exists only while the request runs.
  - Its expiry becomes `PveApiException("The server did not answer within 30 seconds.")`. The caller's own
    cancellation still propagates as cancellation.
- **L4 fixed.**
  - `ReadBodyAsync` reads the content stream in 64 KiB pooled pieces. A success body is refused with "too large" as
    soon as it would pass 16 MiB, whether or not a `Content-Length` was given.
  - An error body is read only up to 64 KiB, for its message, and the rest is dropped. A stream failure mid-body is a
    `PveApiException`.
- **L5 fixed.**
  - `Microsoft.Windows.SDK.NET.Ref` itself has no license file. The Windows SDK license text ("MICROSOFT WINDOWS
    SOFTWARE DEVELOPMENT KIT (SDK) FOR WINDOWS 10") is in `Microsoft.Windows.SDK.Win32Metadata`'s
    `sdk_license.txt`. That package is already restored, as CsWin32's dependency, at the version the viewer's
    `project.assets.json` names.
  - `tools/package.ps1` now includes that text for the projection component, with a note saying where it comes from.
    Nothing was downloaded.
  - Residual gap: the projection package only links
    `https://aka.ms/WinSDKLicenseURL`. That this text is the one the link names is inferred from its title, not
    checked against the web page.
- **Also from the cross-check:**
  - `CredentialStore.List` now clears the secrets `CredEnumerate` returns before `CredFree`.
  - `GetDpiForWindow` stays a `[LibraryImport]`. The launcher has no CsWin32 setup, and AGENTS.md allows
    hand-written `LibraryImport`.
- **Version pin** (coordinator): the launcher now pins the components of Windows App SDK 2.5.1 (2026-09-16), the
  newest release out at least two weeks: WinUI 2.3.9, Foundation 2.3.12, InteractiveExperiences 2.1.9, Base 2.0.4.
  All four are listed explicitly, because WinUI 2.3.9 asks for an InteractiveExperiences 2.1.8 that was never
  published (NU1603). Decision 0038 records the choice and the new sizes.
