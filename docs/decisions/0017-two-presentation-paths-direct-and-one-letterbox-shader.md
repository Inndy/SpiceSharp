# 0017. Two presentation paths: direct and one letterbox shader

- Status: Accepted
- Date: 2026-10-29
- Decided by: agent (spec silent), reviewed by Codex

- **Context:** the draft's presenter sizes the swap chain to the guest and copies dirty rects into it with no shader; when the aspect ratio can't be locked (maximized, snapped, full screen) it allows one letterbox path with a single full-screen-triangle shader; the software profile is 1:1 only. An earlier version padded a stretched swap chain instead, which distorted Fit at the texture limit (verification finding N4) and resized the buffers for layout changes.
- **Decision:** `Viewport.Compute` picks the path per update; the presenter and `MainWindow.GuestRect()` (input mapping, cursor clip and position) use the same result.
  - **Direct** — Fit when the client has the guest's aspect ratio within a pixel of rounding (`WM_SIZING` locks it; with the agent the guest takes the window's size), or 1:1 when the client is exactly the guest's size. The swap chain is the guest's size (`FLIP_SEQUENTIAL`, 2 buffers, `B8G8R8A8_UNORM`, `DXGI_SCALING_STRETCH`, waitable, max latency 1); `ResizeBuffers` only when the guest resolution changes; this update's and the previous update's dirty rects are copied from the CPU framebuffer with `UpdateSubresource` and passed to `Present1` with the scroll rect. An interactive aspect-locked resize presents nothing; DWM stretches the last frame.
  - **Letterbox** — everything else: Fit at another aspect ratio, 1:1 at another size, and the software profile when the window isn't the guest's size. The swap chain is the client's size; the guest lives in a texture updated with the dirty rects; one draw of a full-screen triangle (vertex and pixel shader, point sampler at 1:1, linear when scaled) fills the destination rectangle set as the viewport, mapped through a 16-byte constant buffer so the viewport stays inside the render target even when 1:1 crops. The bars are cleared to the window background (0x202020) once per flip buffer after a layout change. Each update redraws the destination and passes the changed rectangles, transformed to window pixels and widened by one pixel when filtered, to `Present1`; layout changes present in full. `ResizeBuffers` happens on client size changes while letterboxed.
  - The shaders are precompiled with fxc (`vs_4_0_level_9_3`/`ps_4_0_level_9_3`) and embedded as bytes in `src/SpiceViewer/Shaders.cs`, which holds the HLSL, the command lines and hashes. Feature level 9 has no integer shader inputs, so the triangle comes from a 3-vertex immutable buffer instead of `SV_VertexID`.
  - Software profile (`DXGI_ADAPTER_FLAG_SOFTWARE`, vendor 0x1414, or `SPICEVIEWER_FORCE_WARP=1`): 1:1 only ("Fit to window" greyed out), at most 30 presents per second.
- **Reason:** the draft's design: the normal case has no shader and the swap chain can be independently flipped; the letterbox path is uniform by construction (no padded stretch, so N4 cannot occur) and its texture keeps the guest independent of the window size. Verified offscreen on hardware (feature level 11 and forced 9_3) and WARP: window captures matched the framebuffer exactly in direct and 1:1 letterbox layouts and within filtering tolerance for scaled Fit. Whether full screen and maximized windows get independent flip still needs a PresentMon check.
