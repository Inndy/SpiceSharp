# 0024. Settings: portable by default, opt-in install

- Status: Accepted
- Date: 2026-10-29
- Decided by: the human (portable by default, opt-in install, no registry store); details by the agent

- **Context:** the human likes portable software and wants local installation to be opt-in, with preferences in a proper store rather than the registry (2026-10-29). The draft only says to use source-generated `System.Text.Json` where JSON appears.
- **Decision:**
  - **Paths** (`AppPaths`): installed mode iff the exe's directory is `%LOCALAPPDATA%\Programs\SpiceViewer` (full path, case-insensitive); then settings go to `%APPDATA%\SpiceViewer` and the log to `%LOCALAPPDATA%\SpiceViewer`. Otherwise portable: both in `<exe dir>\data\`, probed at startup by creating the folder and a self-deleting file; if that fails (e.g. under Program Files) the installed-mode folders are used and one Info line says so. `viewer.log` moved there with its 1 MB cap unchanged.
  - **File** (`SettingsStore`, `settings.json`, UTF-8, indented): `version: 1`; globals `serverCursor` (`guest`/`hidden`), `scaling` (`fit`/`oneToOne`), `systemShortcuts` (`always`/`fullscreenOnly`/`never`), `resizeGuest`; and `vms` (previous section). Added 2026-10-30: global `videoPacing` (`spacing`/`clock`/`off`, see 0025), read leniently: an unknown value falls back to `spacing` without invalidating the file. Added 2026-10-30: globals `fastJpeg` (bool, default `false`; anything but `true` or `"true"` reads as `false`) and `imageCompression` (`auto`/`lz4`, default `auto`; an unknown value reads as `auto`), see 0028. Serialized with a `JsonSerializerContext` (source generation, string enums, comments and trailing commas accepted, relaxed escaping so titles stay readable); no reflection, no new packages. Read once at startup with a 1 MiB cap. Out-of-range values fall back per field and invalid entries are dropped; a file that isn't valid JSON, has another version or is too large is logged, defaults are used, and it is left alone until the next successful save, which renames it to `settings.json.bad` first.
  - **Writes** only when the window closes and when a setting changes in the system menu; never on a timer or per move/size message. Each write runs on a pool thread, re-reads the file, applies only its own change (one VM entry, or one global), prunes to 200 VMs, writes `settings.json.<pid>.tmp` in the same folder and moves it over `settings.json` (atomic replace). A lock serializes writes within the process, and a named mutex (`Local\SpiceViewer.settings.<hash of the file's full path>`, waited on for at most 5 s) makes the whole read-modify-write exclusive across processes, so viewers of different VMs open at the same time don't drop each other's entries (amended 2026-10-30 after Codex's review reproduced a lost update with re-reading alone). Close waits at most 1 s for the write, in parallel with the session shutdown; an unfinished write leaves the previous file intact. Failures are logged, never thrown.
  - **Install** (`--install`): copies the exe, the three DLLs, README/LICENSE and `source\` (if present) to `%LOCALAPPDATA%\Programs\SpiceViewer` (exe last), copies the portable `settings.json` to `%APPDATA%\SpiceViewer` if none exists there, and registers the .vv association (HKCU only) for the installed exe. `--uninstall` unregisters it and deletes that one folder (refused if it is a reparse point or has no `SpiceViewer.exe`); when run from the folder itself, a detached `cmd /c` started after the message closes polls `tasklist` for this PID about once a second (at most a minute), then runs `rd /s /q` on it, with its working directory outside the folder. Settings and log are kept and their location shown. Results are reported with task dialogs; `--register`/`--unregister` keep working (silently) for portable copies.
  - **Not done:** Start-menu shortcuts (they need `IShellLink` COM, out of scope for now), an Apps & features entry, and any registry use for preferences.
- **Reason:** a single small file beside the exe keeps the zip portable and easy to reset or copy; the install mode gives a fixed location for the association without elevation. Event-only writes keep the energy rules: nothing runs while the viewer idles.
